Storage review

Notes for Thursday

Before we call the new store durable, check the boring parts. Every commit goes to the write-ahead log first, and we fsync it before telling the client the data is safe. A flush on its own only gets the bytes as far as the kernel. Compaction writes a fresh file and renames it over the old one, so it also needs fsyncing the directory, or a power cut can quietly undo the rename.

Reads are the other half. The block cache is plain LRU, so one big scan can push out everything hot. MVCC keeps readers from blocking writers, but old row versions pile up until vacuum catches up. And I’d take the memoisation out of the query planner until we know why its plans go stale.

For the reading list: the SQLite notes on atomic commit, and the Glasswing post everyone in the security channel keeps sharing.
